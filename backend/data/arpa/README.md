# خروجی‌های نرم‌افزار حسابداری آرپا

این پوشه در گیت هست؛ **محتوایش هرگز نیست**.

فایل‌ها نام و تلفن و کد ملی ~۲۰۰۰ طرف‌حساب واقعی و مبلغ ۱۱۰۰ فاکتور را دارند.
تاریخچه‌ی گیت پاک‌شدنی نیست: یک commit اشتباه این داده را برای همیشه در هر
clone نگه می‌دارد، حتی بعد از حذف. مثل `data/didar`، فایل‌ها دستی روی سرور
آپلود می‌شوند.

## چه فایل‌هایی

از منوی **فروش ← گزارشهای خلاصه فروش** در آرپا، با بازه‌ی تاریخ باز:

| فایل | گزارش |
|---|---|
| `اشخاص کلی.xlsx` | فهرست طرف‌حساب‌ها (تب معرفی) |
| `فروش کل*.xlsx` | لیست فاکتورهای فروش و مرجوعی |
| `*جزئیات فروش*.xlsx` | جزئیات فاکتورهای فروش و مرجوعی |

نام فایل‌های فروش با `*` تطبیق داده می‌شود، پس می‌شود یکی برای هر سال گذاشت —
`فروش کل404.xlsx` کنار `فروش کل.xlsx` — و هر دو با هم خوانده می‌شوند. بازه‌ها
نباید همپوشانی داشته باشند، وگرنه یک فاکتور دو بار شمرده می‌شود.

## اجرا

```bash
python manage.py import_arpa_parties  --dir data/arpa --check   # گزارش، بدون نوشتن
python manage.py import_arpa_parties  --dir data/arpa
python manage.py import_arpa_invoices --dir data/arpa
```

ترتیب مهم است: فاکتور بدون طرف‌حسابِ وارد‌شده رد می‌شود.

هر دو دستور idempotent‌اند — اجرای دوباره چیزی تکراری نمی‌سازد و مواردی که
زیر بازبینی‌اند را دست نمی‌زند. `deploy.sh` هر دو را صدا می‌زند؛ اگر فایل‌ها
نباشند، پیام می‌دهند و رد می‌شوند بدون اینکه deploy را بشکنند.

## بعد از بازبینی

فاکتور طرف‌حسابی که هنوز در صف بازبینی است وارد نمی‌شود. بعد از خالی کردن صف
در `/crm/match-review`، دوباره `import_arpa_invoices` را بزن تا برداشته شوند.
