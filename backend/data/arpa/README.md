# خروجی‌های نرم‌افزار حسابداری آرپا

این پوشه در گیت هست؛ **محتوایش هرگز نیست**.

فایل‌ها نام و تلفن و کد ملی ~۲۰۰۰ طرف‌حساب واقعی و مبلغ فاکتورها را دارند.
تاریخچه‌ی گیت پاک‌شدنی نیست: یک commit اشتباه این داده را برای همیشه در هر
clone نگه می‌دارد، حتی بعد از حذف. فایل‌ها دستی روی سرور آپلود می‌شوند.

## deploy این‌ها را اجرا نمی‌کند — عمداً

قبلاً `deploy.sh` هر بار import را می‌زد و این نتیجه را داشت: مشتری‌ای که در
برنامه حذف شده بود برمی‌گشت، و ویرایش دستی تیم با هر نسخه‌ی جدید پاک می‌شد.
بارگذاری داده‌ی حسابداری کار جداگانه‌ای است که **بعد از آپلود خروجی تازه**
انجام می‌شود، نه با هر تغییر کد.

## چه فایل‌هایی

از منوی **فروش ← گزارشهای خلاصه فروش** در آرپا:

| فایل | گزارش |
|---|---|
| `اشخاص کلی.xlsx` | فهرست طرف‌حساب‌ها (تب معرفی) — همیشه کامل، بدون فیلتر تاریخ |
| `فروش کل*.xlsx` | لیست فاکتورهای فروش و مرجوعی |
| `*جزئیات فروش*.xlsx` | جزئیات فاکتورهای فروش و مرجوعی |

یک فایل فروش برای هر سال: `فروش کل404.xlsx` کنار `فروش کل.xlsx` (سال جاری).
همپوشانی بازه‌ها چیزی را دو بار نمی‌شمارد — هر فاکتور با (نوع، شماره، تاریخ)
یکتاست — ولی بهتر است هر فایل فقط سال خودش را داشته باشد.

برای به‌روزرسانی سال جاری، فایل‌های ۱۴۰۵ را با خروجی تازه (از `1405/01/01`
تا امروز) **جایگزین** کن. فایل‌های سال‌های بسته‌شده دست نمی‌خورند.

## اجرا روی سرور

```bash
cd ~/bi-platform/backend
source /home/ntpbiir/virtualenv/bi-platform/backend/3.12/bin/activate

python manage.py import_arpa_parties  --dir data/arpa --check   # فقط گزارش
python manage.py import_arpa_parties  --dir data/arpa
python manage.py import_arpa_invoices --dir data/arpa
```

ترتیب مهم است: فاکتوری که طرف‌حسابش وارد نشده رد می‌شود.
`import_arpa_invoices` در پایان فاکتورهای تازه را به معامله‌های دیدار وصل
می‌کند.

## اجرای دوباره چه چیزی را عوض نمی‌کند

- مشتری‌ای که در برنامه **حذف** شده برنمی‌گردد.
- فیلدهایی که در صفحه‌ی مشتری ویرایش می‌شوند (تلفن، آدرس، کد ملی، استان،
  گروه) فقط اگر **خالی** باشند پر می‌شوند.
- مشتری‌ای که تیم **فعال** کرده غیرفعال نمی‌شود. import فقط می‌تواند
  مشتری‌ای را که تازه خرید کرده فعال کند.
- طرف‌حسابِ زیر بازبینی دست نمی‌خورد.

فیلدهایی که فقط حسابداری دارد (کد اقتصادی، شرایط تسویه، خوش‌حسابی) همیشه
با آرپا همگام می‌شوند.

## بعد از بازبینی

فاکتور طرف‌حسابی که در صف بازبینی است وارد نمی‌شود. بعد از خالی کردن صف در
`/crm/match-review`، `import_arpa_invoices` را دوباره بزن. بعد از ادغام
مشتری‌ها، `python manage.py link_invoices` فاکتورها را دوباره به معامله وصل
می‌کند.
